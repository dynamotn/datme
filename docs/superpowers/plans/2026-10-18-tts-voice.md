# Text-to-speech in the author's voice — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Generate audio of selected notes in the author's cloned voice at build time, one TTS model per language, and play it from a ▶ button at the top of the note.

**Architecture:** A `tts` block in `datme.yaml` selects notes by folder or frontmatter and maps languages to models. At build time, a memoised audio index turns each selected note's public text into chunks, sends them to a long-lived VieNeu Python helper over JSON lines, and caches the MP3 under a key that depends only on the text, model and voice. An Astro endpoint publishes the MP3s and the note page shows the button only when a file exists.

**Tech Stack:** TypeScript, Astro, Bun test, zod. VieNeu-TTS v3 Turbo through the `vieneu` Python SDK 3.7.1 run with `uv`, and `lameenc` for MP3 encoding.

**Spec:** `docs/superpowers/specs/2026-10-18-tts-voice-design.md`

## Global Constraints

- One model per language. A language with no configured model gets no audio. Never fall back to another language's model.
- The only model id accepted at launch is `vieneu` (VieNeu-TTS v3 Turbo, `vieneu==3.7.1`, Apache-2.0). Do not use the CC-BY-NC variants or community finetunes.
- The voice sample never enters the repository or the published site. It is read from the path in the environment variable `DATME_TTS_VOICE`.
- Notes with `protected: true` (whole-note password) get no audio. Locked parts are never read; unlocked parts of the same note are.
- Drafts get audio, but only in builds run with `--drafts` (they are not in the vault otherwise).
- A configured model that cannot start, or a missing `DATME_TTS_VOICE`, fails `datme build`. A failure on one note logs `console.warn("[datme] …")` and skips that note.
- The audio cache key is `[model, VIENEU_VERSION, sha256(voice file), sha256(chunks)]` and must not include the site config, so unrelated config edits do not regenerate audio.
- Audio is generated on CI and deployed; it is never committed.
- `bun test --coverage` must keep 100% line and function coverage of `src/`. The real engine is exercised through a fake helper selected by `DATME_TTS_CMD`.
- The browser-only fallback from #6 is out of scope for this plan (my call, allowed by the spec).

## Review Focus

1. A selected note whose whole body is locked or is only code: no MP3, no button (not an empty file). Test in Task 6.
2. A note in `en-US` when only `vi` has a model: no audio. `vi-VN` notes match the `vi` key. Test in Task 2.
3. Folder rule `Podcast` must not match `Podcasts/…`, and must match `Podcast/Sub/…`. Test in Task 2.
4. Editing an unrelated config key (for example `site.title`) must hit the audio cache. Test in Task 4.
5. The helper dying in the middle of a build: notes already done keep their audio; the remaining ones are skipped with a warning, and the build does not hang. Test in Task 5.

### Task 5: VieNeu engine

**Files:**
- Create: `src/lib/tts-engine.ts`, `src/lib/tts/vieneu.py`, `tests/fixtures/tts/fake-engine.ts`
- Test: `tests/tts-engine.test.ts`

**Interfaces:**
- Produces:
  - `const VIENEU_VERSION = "3.7.1"`
  - `class TtsUnavailable extends Error` (message includes how to fix: install `uv`, set `DATME_TTS_VOICE`).
  - `interface TtsEngine { synthesize(model: "vieneu", voice: string, chunks: string[]): Promise<Buffer>; close(): Promise<void> }`
  - `startEngine(): Promise<TtsEngine>` — spawns the command from `DATME_TTS_CMD` (JSON array) or, by default, `["uv","run","--quiet","--with","vieneu==3.7.1","--with","lameenc","python","<abs path of vieneu.py>"]`; resolves after the helper prints `{"ready":true}`; rejects with `TtsUnavailable` if the process exits or fails to spawn first.
  - Protocol, one JSON object per line. Request on stdin: `{"id":1,"model":"vieneu","voice":"/abs/voice.wav","chunks":["…"]}`. Reply on stdout: `{"id":1,"mp3":"<base64>"}` or `{"id":1,"error":"…"}`. Requests are answered in order.
  - `vieneu.py`: loads `Vieneu()` once (CPU/ONNX by default), clones the voice per distinct `voice` path, synthesises each chunk with `ref_audio`, concatenates with 300 ms of silence between chunks, encodes MP3 mono 48 kHz 64 kbps with `lameenc`, and writes the reply line.

- [ ] **Step 1:** Write `tests/fixtures/tts/fake-engine.ts` (run with `bun`): prints `{"ready":true}`, answers each request with `mp3` = base64 of `"MP3:" + chunks.join("|")`; replies `error` when a chunk contains `FAIL`; exits immediately when a chunk contains `CRASH`; exits with code 1 before ready when `FAKE_TTS_NO_START=1`.
- [ ] **Step 2: Write failing tests** with `DATME_TTS_CMD='["bun","tests/fixtures/tts/fake-engine.ts"]'`: synthesize returns the expected bytes; an `error` reply rejects that call only and the next call succeeds; `FAKE_TTS_NO_START=1` → `startEngine` rejects with `TtsUnavailable`; after `CRASH`, pending and later calls reject within 5 s (no hang); a nonexistent command → `TtsUnavailable`; `close()` ends the process.

**Interfaces:**

- Produces:
  - `audioPath(n: Note): string` — the published URL of a note's MP3, the note URL with `.mp3` in the same way `[...md].md.ts` adds `.md`.
  - `audioIndex(): Promise<Map<string, Buffer>>` — memoised per process; keys are `n.url`. Empty map when `site.tts` is undefined. For every lang and every note where `ttsSelected` and `ttsModel(lang)` hold and `noteChunks(n)` is non-empty, read the stable cache under `[model, VIENEU_VERSION, sha256(voice bytes), sha256(JSON.stringify(chunks))]`, otherwise synthesise and write it. A per-note rejection logs `[datme] audio skipped for <key>: <message>` and leaves the note out. Closes the engine when done.
  - `hasAudio(n: Note): Promise<boolean>`.
  - The endpoint's `getStaticPaths` returns one path per entry of `audioIndex()` and `GET` returns the buffer with `Content-Type: audio/mpeg`.
